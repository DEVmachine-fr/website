# Automatisation et IA en local avec n8n

## Introduction

n8n est une plateforme d'automatisation open-source qui permet de créer des workflows complexes sans code (low-code). Dans ce tutoriel, nous allons mettre en place une architecture complète combinant n8n avec Qdrant (base de données vectorielle) et Ollama (LLM en local) pour créer un système de chat capable d'exploiter une documentation personnalisée.

L'objectif est de construire deux workflows :
1. **Workflow d'indexation** : Lire des fichiers markdown et les enregistrer en tant que vecteurs dans une base Qdrant
2. **Workflow de chat** : Permettre une conversation avec une IA qui utilise cette base vectorielle pour répondre aux questions

Nous terminerons par un avis détaillé sur n8n et son adéquation pour ce type de projet.

## Mise en place du projet

### Configuration requise

Avant de vous lancer dans ce projet, soyez conscient que l'exécution locale de modèles d'IA entiers est exigeante en ressources système. Votre machine devra disposer de :
- **RAM** : Au minimum 8 Go (16 Go recommandé)
- **GPU** : Recommandé pour des temps de réponse acceptables
- **Espace disque** : Prévoir plusieurs Go pour les modèles d'IA et l'indexation vectorielle

Si votre configuration est limitée, vous pouvez ajuster les modèles utilisés ou envisager des optimisations plus avancées.

### Qu'est-ce que n8n ?

n8n est une plateforme d'automatisation open-source basée sur une interface visuelle "no-code/low-code". Elle permet de créer des workflows complexes en connectant des "nodes" qui représentent des étapes de traitement (appels API, transformation de données, interactions avec des bases de données, etc.). 

Les principales caractéristiques :
- **Visuelle et intuitive** : Pas besoin de coder pour créer des automatisations
- **Open-source** : Peut être auto-hébergée pour plus de contrôle et de sécurité
- **Extensible** : Intégration avec des centaines de services externes
- **Modulaire** : Les workflows sont sauvegardés en JSON et facilement partageables

### Installation de n8n avec Docker Compose

Créez un dossier **n8n_data** à la racine de votre projet. Ce dossier servira de volume monté et stockera toutes les données de n8n (workflows, credentials, etc.).

Créez ensuite un fichier **docker-compose.yaml** avec la configuration suivante :

```yaml
services:
  n8n:
    image: docker.n8n.io/n8nio/n8n
    user: "1000:1000"
    ports:
      - "5678:5678"
    environment:
      # Gestion des cookies
      - N8N_SECURE_COOKIE=false
      
      # Expérience utilisateur
      - N8N_PERSONALIZATION_ENABLED=false

      # Sécurité et accès aux nodes
      - NODES_EXCLUDE=[]
      - NODE_FUNCTION_ALLOW_BUILTIN=*
      - N8N_BLOCK_FS_WRITE_ACCESS=false

      # Chemins de fichiers
      - N8N_USER_FOLDER=/home/node
      - N8N_RESTRICT_FILE_ACCESS_TO=/home/node

    volumes:
      - ./n8n_data:/home/node
```

#### Détail des paramètres d'environnement

- **N8N_SECURE_COOKIE** : Active la transmission sécurisée des cookies (HTTPS uniquement). Mis à `false` pour le développement local.
  
- **N8N_PERSONALIZATION_ENABLED** : Désactive les questions de personnalisation au premier lancement (non nécessaire pour ce projet).

- **NODES_EXCLUDE** : Par défaut, certains nodes sont désactivés pour des raisons de sécurité car ils donnent un accès élevé au système. Ici, nous les activons tous pour permettre les fonctionnalités avancées.

- **NODE_FUNCTION_ALLOW_BUILTIN** : Les modules Node.js comme `fs`, `crypto`, `moment` sont désactivés par défaut dans les scripts custom. Ici, nous les autorisons tous.

- **N8N_BLOCK_FS_WRITE_ACCESS** : Désactive la restriction d'accès au système de fichiers, ce qui est nécessaire pour notre workflow.

- **N8N_USER_FOLDER** : Définit le dossier où n8n stocke les données utilisateur. Pointant vers le volume, cela persiste les données entre les relancements du conteneur.

- **N8N_RESTRICT_FILE_ACCESS_TO** : Limite l'accès aux fichiers à ce chemin. Sans cette restriction, n8n ne peut écrire que dans le sous-dossier `.n8n/` du dossier utilisateur.

#### ⚠️ Important : Considérations de sécurité

Les paramètres ci-dessus sont volontairement largement ouverts pour faciliter le développement et l'expérimentation. **Si vous exposez votre instance n8n sur le web** (nécessaire pour l'intégrer à d'autres services), vous devez absolument restreindre ces paramètres. 

n8n est devenue une cible privilégiée pour les attaquants en raison de sa popularité, et plusieurs CVE critiques ont été découverts. Respectez le principe du moindre privilège : n'autorisez que ce qui est strictement nécessaire.

### Installation de Qdrant (base de données vectorielle)

**Qdrant** est une base de données optimisée pour stocker et rechercher des vecteurs d'embedding. Elle sera utilisée pour indexer nos documents markdown et permettre à notre agent IA de retrouver les informations pertinentes lors d'une question.

Créez un dossier **qdrant_data** qui servira de volume persistant pour Qdrant.

Ajoutez le service Qdrant à votre fichier **docker-compose.yaml** :

```yaml
services:
  n8n:
    # ... configuration précédente ...
    depends_on:
      - qdrant

  qdrant:
    image: qdrant/qdrant
    ports:
      - "6333:6333"
    environment:
      - QDRANT_API_KEY=your_secure_key  # À changer en production
    volumes:
      - ./qdrant_data:/qdrant/storage
```

#### Démarrage des services

Avant de lancer les conteneurs, organisez vos documents. Créez un dossier **files** dans `n8n_data/` et placez-y tous les fichiers markdown que vous souhaitez indexer :

```
n8n_data/
  files/
    documentation.md
    tutorial.md
    guide.md
```

Lancez les services :

```bash
docker-compose up -d
```

Vérifiez que tout fonctionne :

```bash
docker ps
```

Vous devriez voir n8n et Qdrant s'exécuter. L'interface de n8n est accessible à **localhost:5678** et le tableau de bord de Qdrant à **http://127.0.0.1:6333/dashboard**.

### Installation d'Ollama (LLM local)

**Ollama** permet de faire tourner des modèles de langue (LLM) directement sur votre machine sans dépendre de services cloud payants.

Suivez le [guide d'installation officiel d'Ollama](https://ollama.ai) pour votre système d'exploitation. Une fois installé, vous pouvez télécharger des modèles selon vos besoins.

#### Modèle d'embedding (obligatoire pour Qdrant)

Téléchargez un modèle d'embedding :

```bash
ollama pull nomic-embed-text
```

**Options recommandées** :
- `nomic-embed-text` : Léger (275M), très rapide, excellent pour l'indexation
- `mxbai-embed-large` : Plus précis, plus gourmand en ressources

#### Modèle de chat (pour l'agent IA)

Choisissez un modèle adapté à votre machine. **Important** : Assurez-vous que votre modèle prend en charge les "Function Calling" ou "Tools" pour fonctionner correctement avec n8n.

**Options recommandées** :

```bash
# Léger (3-4 Go RAM)
ollama pull phi:3

# Bon rapport qualité/performances (8 Go RAM recommandé)
ollama pull qwen:8b
ollama pull mistral:7b-instruct

# Meilleure qualité (12+ Go RAM)
ollama pull neural-chat:8b
ollama pull llama2:13b
```

**Comment vérifier si un modèle prend en charge les tools ?**

1. **Via la documentation officielle** : Visitez [ollama.ai/library](https://ollama.ai/library) et consultez la page du modèle
2. **Tester directement** : Lancez Ollama et testez avec un premier workflow n8n simple
3. **Modèles compatibles confirmés** : `qwen:8b`, `neural-chat:8b`, `mistral:7b-instruct`, `phi:3`
4. **Vérifier les capacités** : Cherchez les mots-clés "function calling", "tool use", "agent" dans la description du modèle

Une fois les modèles téléchargés, Ollama démarre automatiquement un serveur accessible localement sur **http://localhost:11434**.

### Création de la collection Qdrant

Avant de configurer n8n, nous devons créer une collection Qdrant pour stocker nos embeddings:

1. Ouvrez le tableau de bord Qdrant : **http://127.0.0.1:6333/dashboard**
2. Cliquez sur **"Create collection"** en haut à droite
3. Remplissez les informations :
   - **Collection name** : `documentations` (ou le nom de votre choix)
   - **Vector size** : `768` (pour `nomic-embed-text`). Adaptez selon votre modèle d'embedding:
     - `nomic-embed-text` → `768`
     - `mxbai-embed-large` → `1024`
   - **Distance** : `Cosine` (par défaut, convient très bien)
4. Cliquez sur **"Create"**

Vérifiez la création en visitant le dashboard. Vous devriez voir la collection listée.

## Configuration de n8n

Accédez à l'interface de n8n à **localhost:5678** et connectez-vous. Nous allons créer deux workflows distincts.

### Workflow 1 : Indexation des documents

Ce workflow lit les fichiers markdown et les enregistre en tant que vecteurs dans Qdrant.

#### Étape 1 : Ajouter un déclencheur

- Cliquez sur le **"+"** en haut à droite de la zone d'édition
- Sélectionnez **"Add a trigger"**
- Choisissez **"Trigger manually"** (pour pouvoir le déclencher manuellement à volonté)

#### Étape 2 : Lire les fichiers markdown

- Cliquez sur le **"+"** à droite du noeud de déclenchement
- Recherchez et sélectionnez **"Read/Write files from Disk"**
- Choisissez **"Read File(s) from Disk"**

**Configuration du nœud** :
- Changez le champ "File(s) Selector" de "Fixed" à **"Expression"**
- Entrez la regex : `**/*.md` (ou `files/**/*.md` si vous avez créé un dossier `files` dans `n8n_data`)

#### Étape 3 : Configurer les credentials Qdrant

- Cliquez sur le **"+"** à droite du noeud de lecture des fichiers
- Recherchez **"Qdrant"** et sélectionnez **"Qdrant Vector store"**
- Choisissez **"Add documents to vector store"**

**Configuration Qdrant** :
- Créez un nouveau credential Qdrant avec l'URL : `http://qdrant:6333`
- Allez sur le **tableau de bord de Qdrant** (http://127.0.0.1:6333/dashboard) 
- Créez une collection nommée **"Documentations"**
- Retournez dans n8n et sélectionnez cette collection (champ "Qdrant collection" → "By ID" → "Documentations")

#### Étape 4 : Configurer l'embedding

- Cliquez sur le **"+"** en bas à gauche du nœud Qdrant (sous "Embedding")
- Recherchez et sélectionnez **"Embeddings Ollama"**
- Créez un credential Ollama avec l'URL : `http://host.docker.internal:11434` (ou `http://localhost:11434` si Ollama est sur le réseau docker)
- Sélectionnez le modèle d'embedding : `nomic-embed-text`

#### Étape 5 : Configurer le chargeur de documents

- Cliquez sur le **"+"** en bas à droite du nœud Qdrant (sous "Document")
- Sélectionnez **"Default Data Loader"** (pas de modification nécessaire)

#### Lancement du workflow

Cliquez sur **"Execute Workflow"** pour indexer vos documents. Vérifiez dans le tableau de bord de Qdrant que la collection s'est bien remplie.

---

### Workflow 2 : Chat avec agent IA

Ce workflow permet de discuter avec un agent IA qui utilise la base Qdrant pour répondre aux questions.

#### Étape 1 : Ajouter un déclencheur de chat

- Créez un **nouveau workflow**
- Cliquez sur le **"+"** en haut à droite
- Sélectionnez **"Add a trigger"**
- Choisissez **"On chat message"** (ce noeud permet une interaction interactive)

#### Étape 2 : Ajouter un agent IA

  - Cliquez sur le **"+"** à droite du nœud de déclenchement
  - Recherchez **"AI"** et sélectionnez **"AI Agent"**
  - Cliquez sur **"Add option"** → **"System message"** et décrivez la fonction de l'agent :
  ```
  Tu es un assistant expert en documentation de projet. 
  Réponds aux questions en utilisant les documents de la base de données.
  Sois concis, précis et cite tes sources quand c'est pertinent.
  ```

#### Étape 3 : Configurer le modèle de chat

- Cliquez sur le **"+"** en bas à gauche du nœud Agent (sous "Chat model")
- Recherchez et sélectionnez **"Ollama"** → **"Ollama Chat Model"**
- Sélectionnez le credential Ollama créé précédemment
- Choisissez le modèle : `qwen:8b` (ou adapté à votre configuration)
- Optionnel : Ajustez les paramètres (température, top_p, etc.)

#### Étape 4 : Ajouter la mémoire de conversation

- Cliquez sur le **"+"** en bas au centre du nœud Agent (sous "Memory")
- Sélectionnez **"Simple Memory"** (conserve l'historique de la conversation)

#### Étape 5 : Linking la base de connaissance Qdrant

- Cliquez sur le **"+"** en bas à droite du nœud Agent (sous "Tool")
- Recherchez et sélectionnez **"Qdrant"** → **"Qdrant Vector store"**
- Sélectionnez le credential Qdrant déjà créé
- Mode d'opération : **"Retrieve Documents (As Tool for AI Agent)"**
- Collection Qdrant : Sélectionnez **"Documentations"**
- Description de l'outil (important pour que l'agent sache quand l'utiliser) :
  ```
  Cet outil vous permet de rechercher dans la base de documentation du projet.
  Utilisez-le pour trouver des informations pertinentes pour répondre aux questions.
  ```
  
#### Lancement du workflow

Le workflow de chat est prêt ! Cliquez sur le **bouton de test** (icône de dialogue) en bas à gauche de l'interface n8n. Vous pouvez maintenant saisir des messages et votre agent IA devrait répondre en exploitant la documentation indexée.

## Avis et conclusions sur n8n

Après avoir construit cette architecture avec n8n, voici mon analyse détaillée de la plateforme, ses forces et ses limitations.

### Avantages

**1. Interface visuelle et intuitive**
- Le système de nodes permet une compréhension rapide du workflow sans plonger dans du code
- La visualisation du flux de données est claire : vous voyez exactement ce qui entre et sort de chaque étape
- Le debugging est grandement facilité : cliquez sur un node pour voir ses entrées/sorties

**2. Modularité et réutilisabilité**
- Les workflows sont sauvegardés en JSON et facilement partageables
- Vous pouvez copier/importer des workflows construits par d'autres utilisateurs
- La communauté partage régulièrement des templates prêts à l'emploi

**3. Extensibilité et intégrations**
- Centaines de services intégrés (APIs, bases de données, services cloud, etc.)
- Support natif des webhooks et des triggers externes
- Possibilité d'ajouter des nodes custom en JavaScript/Python

**4. Open-source et auto-hébergeable**
- Contrôle total sur vos données (aucune dépendance à un service tiers payant)
- Adaptation facile à vos besoins spécifiques
- Déploiement sur votre infrastructure

**5. Journaux et traçabilité détaillés**
- Historique d'exécution conservé pour chaque workflow
- Possibilité de retracer chaque étape d'une exécution

### Inconvénients

**1. Problèmes de sécurité critiques**
- n8n est devenue une cible pour les hackers en raison de sa popularité croissante
- Plusieurs CVE critiques ont été publiées ces dernières années
- La plateforme a réagi en restreignant de nombreuses fonctionnalités par défaut, ce qui complexifie la configuration

**2. Configuration de sécurité complexe**
- Trouver le bon équilibre entre fonctionnalités et sécurité demande une expertise
- La documentation sur les best practices de sécurité est insuffisante
- Une mauvaise configuration peut exposer votre système à des risques

**3. Performance et scalabilité limitées**
- L'exécution simultanée de workflows complexes peut saturer rapidement une machine locale
- Pas d'optimisation native pour les opérations très gourmandes en ressources
- Les modèles d'IA en local compliquent davantage ce problème

**4. Support des agents IA encore immature**
- **Pas de streaming des réponses** : Vous attendez la génération complète avant d'afficher la réponse
- **Problèmes de timeout** : Une conséquence directe de l'impossibilité de streamer les réponses est qu'un traitement long peut dépasser la limite par défaut (5 minutes)
- **Bugs persistants** : Certaines intégrations avec langchain/ollama peuvent renvoyer des réponses mal formatées

**5. Bugs et regressions non corrigés rapidement**
- Historique de bugs prenant plusieurs mois à être corrigés
- Exemple : Une régression dans l'intégration langchain/ollama rendait le chat inutilisable pendant une longue période
- Nécessite parfois des workarounds complexes (forcer des versions de dépendances)

**6. Manque de maturité en production**
- Moins de retours d'expérience sur les déploiements critiques comparé à d'autres solutions
- Versioning des workflows peut devenir compliqué
- Monitoring et alertes natives insuffisants (nécessite une intégration externe)

**7. Courbe d'apprentissage sur les workflows complexes**
- Les workflows visuels simples sont faciles, mais les architectures complexes deviennent rapidement peu intuitives
- Parfois, du code custom en JavaScript reste nécessaire pour des logiques avancées

### 📊 Verdict et recommandations

**n8n est une solution prometteuse** pour les cas d'usage suivants :
- ✅ Automatisations simples et moyennes (ETL, synchronisation de données)
- ✅ Intégrations entre plusieurs services
- ✅ Prototypage rapide de workflows
- ✅ Équipes sans expertise DevOps forte

**Cependant, j'hésite à la recommander pour :**
- ❌ Environnements de production critiques (nécessite une expertise approfondie en sécurité)
- ❌ Systèmes d'IA avancés en local (manque de maturité, performance insuffisante)
- ❌ Workflows très complexes ou nécessitant une très haute disponibilité

**Conclusion globale** : n8n est un outil puissant qui simplifie grandement certains processus d'automatisation. Cependant, pour l'intégration d'IA locale et les déploiements en production, il nécessite une expertise avancée pour gérer les enjeux de sécurité et de performance. Après cette première expérience, n8n semble encore manquer de maturité pour des systèmes d'automatisation complexes, mais cela pourrait changer avec les évolutions du produit et une meilleure maîtrise de celui-ci.
